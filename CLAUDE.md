# stream-racer-api

BepInEx plugin for Stream Racer. Port 8793 (config `api.Port`). Build/install: `./install.sh`; the game must be closed to swap the DLL (Windows locks it).

- `src/GameNames.cs` + `src/GlobalUsings.cs` are the only places obfuscated game names live (type aliases like `Vehicle`, string constants for Harmony/reflection targets, extension methods like `vehicle.Profile().Login()`); an update that renames one makes that route return 501. Grep `[A-Z]{11}` outside those two files must stay empty.
- Internal state is enums, converted at the API edge only: `CameraMode` (`Cam.Mode`, `ToApiString()` = the `mode` string, null for None), `VehicleState` (`Game.StateOf`), `GameScreen` (`Game.ScreenState`, unknown panel/scene names pass through raw). All three live in `src/States.cs`.

## Layout (src/)
- `Plugin.cs` HttpListener, SSE, auth, embedded ui/, per-frame ticks, hotkey · `Routes.cs` URL → action · `Patches.cs` Harmony hooks · `Settings.cs` persisted page settings + auto-join · `Pure.cs` engine-free logic (unit-tested) · `Minimap.cs`, `Credits.cs`, `TwitchAuth.cs`, `Updates.cs`, `Webhooks.cs`.
- `Game/` = `static partial class Game`, one concern per file: `Game.Vehicles.cs` (lookup, DTOs, snapshot, pos frame, `StateOf`, crash tracking), `Game.Actions.cs` (boom, boost, auto-boost, respawn pool, slow, finish, kick), `Game.Lobby.cs` (join, maps, lobby, screen state, start/end/next), `Game.Perks.cs` (tiers, follower lookup, GrantPerks, PerksDto), `Game.Colors.cs` (parse/set/apply, leaderboard + lobby row names), `Game.Chat.cs` (SayInChat, ChatStatus, chat commands), `Game.Track.cs` (track points, boost zones, finish line), `Game.Images.cs` (avatars, custom images, row images).
- `Camera/` = `static partial class Cam`: `Camera.cs` (state, geometry helpers, FOV, auto toggle), `Camera.Shots.cs` (follow/wide/free, custom shots + `Tick`, prop cams), `Camera.Director.cs` (coverage rule, candidates, the director loop).
- `ui/` is served straight from embedded resources: React/zustand/htm via esm.sh import map, Pico CSS. No bundler. One `.js` + `.css` per page/component, shared tokens in `ui/shared.css`.
- UI layout: `ui/pages/<page>.js` composes `ui/pages/<page>/<Card>.js` (one card / form per file, sharing the page's CSS via the page's `useCss`); `ui/components/` = pieces used by several pages (racers timing board, roster Card/TwitchLookup); `ui/lib/` = the only home of shared helpers: `html.js` (htm + `useCss`), `api.js` (`api()`, token storage, `authHeaders`, `withToken`), `toast.js`, `text.js` (`escapeHtml`, `ordinal`, `initialsOf`), `files.js` (`readFileAsDataUrl`), `query.js` (browser-source `?token=`), `defaults.js` (`OVERLAY_DEFAULTS` / `MINIMAP_DEFAULTS`, shared by the Settings cards and the browser sources). No React imports in `lib/` except `html.js`, so the plain-DOM overlays can use it. New `ui/` subfolders are embedded by the csproj glob and served by `ServeUi` (`"ui/" + path`) without any C# change.
- UI naming: no single-letter identifiers except loop indices and coordinates (`event` not `e`, `racer`/`vehicle`/`response`/`settings`/`snapshot`/`element`…), function names are verbs, every file starts with a header comment saying what it is. `store.js` documents the store in JSDoc typedefs (`Vehicle`, `Snapshot`, `CameraState`, `Settings`, `UiSettings`); the PUT /settings body is `pick(next, SETTINGS_KEYS)`; SSE handlers are named (`onSnapshot`, `onBoostChange`, `onCamera`, `onScreen`, `onSettings`). `tests/api/events.test.ts` and `tests/ui/pages/api.spec.ts` parse `GROUPS` / `EVENTS` from `ui/pages/api.js` by regex (`{ method: "GET", path: "…"` and `const EVENTS = [` … `];`), so those tables stay in that file.
- Page settings persist server-side (`/settings`), not localStorage; only the API token is per-browser.

## Third-party bots (e.g. voisona-bot's TTS-chan)
- One roster on the Bots page: Twitch bots and custom bots are the same list. Per card: ★ auto-join, ↯ auto-boost, Join now, ✕.
- `settings.botOptions[login].autoBoost=false` = the mod never spends that car's boosts; the bot does it via `POST /boost/:login/use`
  using `GET /track/zones` (straights: <12° turn, flat, ≥55 long, clamped to the finish). `PUT /settings` merges, so a bot can send only its keys.
- `lobby` SSE fires when the lobby is joinable (after the scene reload), not at NewGame. `race_start` may precede the circuit: retry `/track/zones`.
- `Game.Ended` (race over → next lobby): screen = `postgame`, `/join` and `/race/start` refuse (old cars still in scene; joining would duplicate the field). Use `POST /race/next`.
- `settings.webhooks` [{event,url,method,header,body,enabled}] fire from `Plugin.Emit` (src/Webhooks.cs). Auto camera is OFF by default; `AUTO=1 sr-cycle.sh` turns it on for tests.
- Reference client: `D:\streaming\voisona-bot\src\streamracer\index.js` (registers, auto-joins, qwen picks zones, boosts, race_end chat line). `node src/streamracer/index.js` runs it standalone.
- TTS-chan: `!race auto` = join & race every lobby (default on). `!race host on` (env `STREAM_RACER_HOST=1`): home → `/lobby?map=<random official>` → `lobby` event → chat/voice → `/race/start` (= press START: the game's own countdown is the join window; `STREAM_RACER_LOBBY_WAIT` adds seconds before pressing it) → commentary on boom/finisher/race_end → `/race/next` 20 s after `race_end`. Snapshot now carries `map {id,name}`.
- UI routes are real paths (`/controls`, `/camera`, `/bots`, `/settings`, `/api`): `Plugin.Handle` serves index.html for those when the request `Accept`s text/html, JSON otherwise (so `GET /settings` still works for fetch/curl). Old `#/page` links are rewritten client-side.
- Screenshots of the UI: `node "%TEMP%/sr-cdp.mjs" <url> <js-expr> <png>` drives chrome-headless-shell over CDP. Do NOT use `--screenshot --timeout`: that flag freezes page JS before fetches apply and shows default settings.
- Custom bots with no color get `Game.AutoColor(login)` (palette by login hash).
- "Add all of chat" (Controls → Race) needs Twitch's chatters list (`moderator:read:chatters`), which the game token lacks: the page POSTs to the bot (`ui.chatJoinUrl`, default `http://127.0.0.1:8788/race/join-chat` on voisona-bot's speak server, CORS *). Chat: `!race chat`. Lobby padding when TTS-chan hosts: `!race pad off|fill [n]|all` (roster bots added right before she presses START).
- UI people pieces live in `ui/components/roster.js` (TwitchLookup, Card, Grid, Empty, useTwitchUsers) and are shared by Bots (`pages/bots/BotCard.js`) and the Settings auto-join list (`pages/settings/AutoJoinCard.js`). `Card` takes `person`.
- Version: `Plugin.Version` (also the BepInPlugin version) → `GET /version` {api, game, unity, bepinex}; `!race version` in chat. Semver from conventional commits via `scripts/post-commit` (`cp scripts/post-commit .git/hooks/` once per clone): `feat:` minor, `fix:`/other patch, `!`/BREAKING CHANGE major; `SKIP_BUMP=1` skips. The build stamps `git rev-parse --short HEAD` into the assembly (`Plugin.Commit`).
- In-game leaderboard: since the Oct 2026 build the game paints each row's name + colour bar from the profile colour itself (in `SetVehicle`, only when the row is built), so we no longer colour it; `SetColor` re-calls `item.SetVehicle` (and `MinimapView.BindVehicles`) so a mid-race colour change shows. We still add a round picture (custom image or Twitch avatar) and a completion percent (`src/Game/Game.LeaderboardExtras.cs`, fed by `Game.DecorateLeaderboard`); switches `settings.leaderboardAvatars` / `leaderboardPercent`. Long names auto-shrink instead of truncating.
- Chat `!race respawn` / `!respawn` (settings.respawnCommand = alias list `a|b` or `a, b`, Pure.CommandAliases; respawnCommandEnabled, Settings → Chat commands) respawns the typer's own car during a race (Game.OnChatMessage). Same for `settings.colorCommand` (`!race color|!color`). Old files with the single `!race respawn` / `!race color` are upgraded to the alias pair on load (Settings.Upgrade). `!race help` in voisona-bot reads these settings.
- Chat replies (`settings.chatReplies`, default on): `Game.SayInChat` sends through the game's own TwitchLib client (the `TwitchCommandListener` field named by `GameNames.ChatClient`, logged in as the streamer with the game token). `GET /chat` reports `canSend` = that token has `chat:edit` (validated hourly at id.twitch.tv); without it Twitch drops the line silently, so bots should relay the `color` / `denied` SSE events instead. `POST /chat/say?text=` for bots/tests.
- Perks: `Pure.ExtraBoosts` decides, `Game.GrantPerks` applies once the backend title is in (follower part after the Helix lookup). Follower checks need `settings.twitchToken` (+ `twitchClientId`) with `moderator:read:followers`; with none, `followerChecks` = `"no token"` in `/settings`, the `perk` event and `GET /perks/:login` (which lists `why[]`). Lookup failures are not cached (`Game.FollowerCheckError`, status `"unknown"`); a new token clears the cache.
- Boost pools: `boost` (pool spend, any path, via the `GameNames.VehicleUseBoost` postfix; DTO carries `boosts` left) and `boosts` `{login, boosts, delta}` from `Game.AddBoosts` (/add, perks) and once per car at race_start (`Game.EmitBoostPools`).
- Camera director toggles: `settings.camera.shots.{grid,high,side,sweep,pack,front,chase,orbit,overhead,prop,finish,duel,pileup,boom}` (Settings.CameraOpts, keys in `Pure.ShotKeys`, missing key = on). `Cam.On(key)` gates every director pick (`Pure.ShotKind` maps `high2` → high, `front:login` → front; `wide:` has no toggle); manual `POST /camera/<shot>` ignores them. `GET /camera` / the `camera` event carry `shots`.
- Saved colors in the lobby: `Patches.BeforeAdd` (AddVehicle prefix) applies `settings.colors` before the game builds the row; the list-item postfix paints the row NAME via `Game.ColorRowName` (`colorLeaderboard` switch + `perks.coloredNames` tier; the game itself only colours a swatch there); `SetColor` repaints open lobby rows.
- `tests/support/installedFeatures.ts`: API tests about newer settings sections skip (with a reason) when the installed DLL predates them; `raceGlobalSetup.ts` recognises `--dir tests/api` whether relative or absolute.
- In-game credits (Settings → Credits) get an "API" block from `src/Credits.cs`: version (green/red/white by `Updates.UpToDate`), commit (`Plugin.Commit`, stamped from `git rev-parse` at build, "dev" outside git), developer, clickable Twitch link. Update check: `api.UpdateUrl` config → JSON `{version, url}`, fetched hourly (`src/Updates.cs`); `GET /version` and the page header show it.
- Dev routes (undocumented): `GET /find?q=<path substring>` (GameObjects + components + TMP text), `POST /find/click?path=`, `POST /find/panel?name=Home|Play|Settings`, `POST /find/scroll?path=&pos=`.
- UI rule: never define a component inside another component's render (e.g. `const NumberField = () => …` inside a page). Pages re-render 60×/s on `pos` during a race, and a new component identity remounts the `<input>`, wiping what's being typed. `NumberField`/`SelectField` live at module level in `pages/settings/fields.js` and `pages/controls/FieldCard.js`.
- Mini map (Oct 2026 game build): the in-game map is the GAME's own (`MinimapView`); ours is gone. `minimap.enabled` / `POST /minimap` only show/hide the game's (`Minimap.Tick`). `/minimap` draws the game's road picture (`GET /minimap/track.png`, read back from its RenderTexture) and places dots with its projection (`GET /track` → `map {cx,cz,ex,ez,image}`, u = 0.5+(x−cx)/ex, v up); before the game has captured the map it falls back to the route line. The rest of `settings.minimap` is the browser page's look.
- Browser sources are separate: `/overlay` = horizontal bar only (`?size&names&accent`), `/leaderboard` = vertical top-N only (`?rows&side&scale`, saved as `overlay.board/boardSide/boardScale`), `/minimap`. `ServeUi` maps `overlay|leaderboard|minimap` → the .html (not in `Pages`, which is the React app's routes only).
- `ui/overlay-shared.js` owns what the bar and the list share: event stream + reconnect, snapshot + `pos` patching, look settings (`feed.look`, defaults from `lib/defaults.js`), `avatarHtml`, and the race phase. Both draw nothing outside a race: `race_end` → cars fade ~1 s (`body.race-over`), then `body.no-race` until `lobby`/`race_start`; a lobby shows the field only with `settings.overlay.showInLobby` (default off). The RIP/finish banner has its own 3 s timer so it outlives the fade.
- Settings → Overlay look is two groups, "Horizontal bar" and "Leaderboard" (rows, size = scale, anchor side, link builder like the mini map's).
- Camera page → Director → "Director uses": one switch per `settings.camera.shots` key (grid, high, side, sweep, pack, front, chase, orbit, overhead, prop, finish, duel, pileup, boom; missing key = on), saved via `saveSettings({ camera })` (`camera` is in `SETTINGS_KEYS` in store.js). Lives in `pages/camera/DirectorShots.js`; the shot buttons in `pages/camera/CameraControls.js` (also on Controls when `settings.ui.cameraOnControls`).
- Boost counters are live: store.js (`onBoostChange`) patches `snapshot.vehicles[login].boosts` (and `me.boosts` for the streamer) from the `boost` and `boosts` SSE events; the next `positions` snapshot stays the truth.
- Bots page layout rules (roster.css / bots.css): badges are an in-flow slot between the tools row and the picture (never absolute over the avatar), `.lg` clips with an ellipsis, `.cbform > label > *` (not `label > *`, which broke the nested file-picker label), the Add custom button is `max-content`, the topbar wraps below ~1000 px instead of clipping tabs.

- Defaults per the game's creators (Sep 2026): no extra boosts (`perks.boost*` = 0) and chat respawns off (`respawnLimit` 0; -1 = unlimited). `POST /respawn/me` = the host's own car, never counted. Mini map: `enabled` is the game's in-game map only (the /minimap page always works), background alpha 0 by default, names sit to the right of their dot and never move (the view reserves room for ~12 chars on the right).
- Mini map title: `minimap.mapTitle` (name, on) and `minimap.mapAuthor` (author line, off) with `mapTitleAlign`/`mapAuthorAlign` (left|center|right, icon picker on Settings), drawn by `/minimap`; query params `?mapTitle=0&mapAuthor=1&mapTitleAlign=left`.
- `!race show` / `!show` (settings.showCommand) emits the `show` event; `/minimap` pops that racer's name for 5 s even when `minimap.names` is off.
- Colours: a racer keeps the colour they picked with the colour command; otherwise their Twitch chat colour is used (captured from any message, `Game.NoteTwitchColor`), so names are only white when Twitch says so.
- Director: the overhead (`Cam.OverheadHold` 9 s) comes back every `Cam.OverheadEveryCuts` (2) cuts, with `Cam.OverheadEvery` (45 s) only as a backstop for a long-held shot so viewers can see the whole field; gated by the `overhead` shot switch on the Camera page.
- Percent: `Game.FinishDistance` uses the first finisher's covered distance once someone finishes (exact), else the finish-line trigger, else the route length; the game's own `finishAt` is never used because it sits well short of the line. Nothing reads 100 until the car has finished.
- Horizontal bar spacing: `overlay.spreadMode` "field" (default; the leader paces the bar and the field is stretched out behind by their gap) or "track" (raw progress); `?spreadMode=`.
- Director shot ranking: behind-the-car views win (chase +4, wide follow +3, pack/high +1 on top of coverage) so racers can read the road ahead and time a boost.
- Opening: the grid shot (`Cam.GridHold` 6 s) then a high overview (`Cam.HighHold` 10 s) run before every other director rule and re-take the free cam each pass, because the game aims its own camera at the grid when a race starts.
- Pack shot: hangs off the group centroid with a route-direction and spread that are both eased, and pans/eases slower than the other shots (it used to anchor on the rear car's live heading, which jittered every frame).
- Finish distance comes from walking the whole route and taking the LAST place it passes the finish trigger (a lap passes it twice; the first pass is the grid). The distance the first finisher covered is only a fallback.
- Ranking puts finishers first in the order they crossed, then everyone else by ground covered. Finished cars stop moving, so ranking on distance alone let the next car overtake the winner.
- Cars are set to Rigidbody interpolation at race start (Cam.KeepCarsSmooth). Physics steps slower than the frame rate, so an uninterpolated car shudders against a camera that moves every frame, and its name label with it.
- Everything per-frame is time-based (the game's fps went up): Uma spring Drag/Stiffness are per 60 fps frame, scaled by `SpringTunedFps`.
- All camera smoothing uses Cam.SmoothDelta (deltaTime capped at 50 ms) so one long frame cannot jolt the shot.
- Finish distance, best source first: what the first finisher actually covered, else the distance measured off the track (Game.FinishLine samples the whole route, matches every FinishLine-tagged gate and takes the furthest crossing past 35% of the route), else the game's own finishAt. The mapped value is only trusted within 0.6x-1.8x of the game's finishAt: matching the wrong gate once put everyone at 99% three seconds in. GET /track/zones reports raceDistance and usedForPercent.
- Pack, side and high all frame the group through Cam.GroupFrame: road direction, not car heading, with the direction and spread eased. Taken raw they shudder.
- The game sets a finished car's progress to 1e9 so it sorts to the top of the order. It is a marker, never a distance: Game.RememberProgress keeps each car's last real progress (60 Hz from PosFrame, 4 Hz from TrackStates) and that is what LearnFinishDistance uses. Taking 1e9 as the race distance once put everyone at 0% to FIN.

- Race results: `settings.sendResults` (default true). False = `Patches.KeepResultsLocal` (prefix on `MapApi` `GameNames.ResultUpload`, the POST /RaceResult that credits season points) answers the game with `Game.LocalRaceResult()` (places, no points; the same reply the game builds for local test maps) so the post-race screen still runs. `/UserRegisterPreGame` and `/Game` (lobby registration, titles) still go out.
- Local standings: `Game.RecordRace` (race-end postfix) appends one JSON line per race to `BepInEx/config/shibiko.streamracer.results.jsonl` {at (local ISO), map, racers[{login,name,color,place (0 = DNF),finished}]}; `GET /standings?period=day|week|month|all&limit=` (served off the game thread in `Plugin.Handle`) totals them with `Pure.Standings` (finisher = field − place + 1, DNF 0; points → wins → podiums → fewest races; periods = local midnight / Monday / the 1st). Browser source `/rankings?period=&rows=&scale=&title=`; Settings → Race results has the switch + link builder.
- Shrink / grow: `POST /shrink/:x` and `/grow/:x` (x = login | all | N random cars; `?scale&seconds&by&except`, except = the redeemer, left out of all/random), `src/Game/Game.Resize.cs`. Shrink = the game's own shrink ray (`vehicle.ShrinkFor` → GameNames, scale clamped 0.1..1 by the game, restores itself); grow = our coroutine with the same flicker / hold / ease shape (the game can't go above 1). Both announce through the game's `ChaosEffectStatus` banner (SHRINK RAY / GROW RAY) + its shrink sound. Buttons: Controls → Field (×count, `ui.shrinkCount` 10 / `ui.growCount` 3) and 🐜/🦖 per racer.
- Drift: `!race drift|!drift` (settings.driftCommand / driftCommandEnabled) or `POST /drift/:x|me|all` arms the car for its next corner; costs ONE pool boost (never free from chat; API `?free=1`), refunded if no corner within 10 s; bots never auto-drift. `src/Game/Game.Drift.cs` (all knobs are `Drift*` consts at its top, untuned in live races): corner = `Pure.TurnAhead` over the route, rear sideways stiffness lowered + `m_SteerHelper` off + yaw push capped by slip angle (`Pure.DriftYawRate`), exit by `Pure.DriftOver`, mini-turbo `Pure.DriftTurbo` via `Game.Boost`. Waits while the game's GripFor runs, makes the game snapshot its grip baseline first (`vehicle.SaveGripBaseline`), restores friction exactly on exit / race end (`Game.StopDrifts`) / error. SSE `drift` {login, phase armed|start|end|refund, seconds, turbo}.
- Road surfaces: `POST /surface/ice|puddles|mud|snow?count=&length=`, `/surface/clear`, `GET /surface` (`src/Game/Game.Surfaces.cs`, maths in Pure surfaces section + `tests/unit/Pure/SurfaceTests.cs`). A patch = route distance [start,end] x lateral extent (puddle = the oval inside it); each ~15 Hz tick maps a car to (progress + along, lateral) via `Pure.RouteFrame` and applies grip through `vehicle.GripFor` (refreshed) and top speed + drag through the `AfterAiSurface` postfix. Flat Sprites/Default meshes dropped onto the road by raycast. Cleared at race end / NewGame (`Weather.EndOfRace`); `surface` SSE. `RoadHalfWidth` (6) is a guess: tune in game.
- Weather: `POST /weather/rain|snow|fog?seconds=`, `/weather/clear`, `GET /weather` (`src/Weather.cs`): code-built ParticleSystems following `Camera.main` (needs `lib/UnityEngine.ParticleSystemModule.dll`; `UpdatePrompt` needs `lib/UnityEngine.IMGUIModule.dll`, both copied from the game's `StreamRacer_Data/Managed`), RenderSettings fog (scene values restored on clear), rain lays puddles every 10 s, snow lays snow (+25% an icy corner) every 12 s via `Game.LaySurfaces`. `weather` SSE. Clear keeps laid surfaces.
- Ranked = `settings.sendResults` (switch on Controls → Race and Settings → Race results). On: results go to the game's servers and the mod keeps to the game's own racing: `Pure.RankedBlocks` makes the API answer 403 for boom via API, free/extra boosts (`/boost/:x`, `/boost/:x/add`), speed, shrink, grow, drift, weather, surfaces, finish and respawns (except `/respawn/me`); chat `!drift`/`!respawn` get "ranked race" replies, perk boosts are not granted, and switching it on clears weather/surfaces/drifts/slows (`Game.EnterRanked`).
